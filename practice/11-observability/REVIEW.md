# Review: 11 Observability

Контрольные вопросы, по которым я буду оценивать логирование, метрики и эксплуатацию.

---

## Структурированные логи

- [ ] Логи выводятся в формате JSON (не `console.log("Error:", err.message)`)?
- [ ] Каждая запись содержит обязательные поля: `timestamp`, `level`, `message`?
- [ ] Уровни используются по назначению: `debug` — подробности разработки, `info` — нормальные события, `warn` — потенциальные проблемы, `error` — сбои?
- [ ] Нет `console.log` для логирования в production-коде — только через логгер?
- [ ] Стек трейс ошибки логируется как структурированное поле, не конкатенацией строк?
- [ ] Нет логирования паролей, токенов, PII (персональных данных) даже на уровне `debug`?

## Request ID / Correlation ID

- [ ] Каждый входящий запрос получает уникальный `request_id` (UUID или nanoid)?
- [ ] `request_id` принимается из заголовка `X-Request-ID` если он пришёл от клиента (для трейсинга между сервисами)?
- [ ] `request_id` присутствует во всех логах этого запроса — от начала до конца обработки?
- [ ] `AsyncLocalStorage` используется для передачи `request_id` без явной передачи параметра в каждую функцию?
- [ ] `request_id` возвращается клиенту в заголовке ответа `X-Request-ID`?

## Health Check

- [ ] `GET /health` endpoint реализован?
- [ ] Endpoint проверяет не только что процесс жив, но и что зависимости доступны (БД, Redis)?
- [ ] Ответ имеет структуру: `{ status: "ok"|"degraded"|"error", checks: { db: "ok", redis: "ok" } }`?
- [ ] При недоступности зависимости возвращается `503 Service Unavailable`, не `200`?

## Метрики

- [ ] Логируется время обработки каждого запроса (latency)?
- [ ] RPS можно вычислить по логам (timestamp + count)?
- [ ] Ошибки (4xx, 5xx) логируются с кодом статуса — можно посчитать error rate?
- [ ] Нет одного "жирного" лога на весь запрос без промежуточных точек для диагностики?

## Graceful Shutdown

- [ ] Обрабатывается сигнал `SIGTERM` (не только `SIGINT`)?
- [ ] При получении сигнала: сервер перестаёт принимать новые запросы, дожидается завершения текущих?
- [ ] Соединения с БД и Redis корректно закрываются перед выходом?
- [ ] Есть таймаут на graceful shutdown (например, 10 секунд) после которого процесс завершается принудительно?
- [ ] Лог-запись "shutdown complete" появляется перед выходом?

## Circuit Breaker

- [ ] В `notes.md` объяснено, что такое circuit breaker и три его состояния: `closed`, `open`, `half-open`?
- [ ] Описан конкретный сценарий, когда circuit breaker нужен в этом проекте?
- [ ] Если реализован — порог ошибок и тайм-аут восстановления вынесены в конфигурацию?

## Postmortem

- [ ] Postmortem описывает: timeline, root cause, impact, resolve, prevention?
- [ ] Нет blame-语言 — фокус на системе, не на ошибке конкретного разработчика?
- [ ] Выводы предлагают конкретные action items, не абстрактные "быть внимательнее"?
