## Event Loop — понимание

- [ ] Сниппет `event-loop-demo.js` демонстрирует правильный порядок: `nextTick` → `Promise.then` → `setTimeout` → `setImmediate`?
- [ ] В комментариях или `notes.md` правильно объясняется, почему именно такой порядок?
- [ ] Различие между микро-задачами (microtasks) и макро-задачами (macrotasks) объяснено корректно?

## Промисы и async/await

- [ ] Функция реализована сначала через `new Promise()`, затем переписана через `async/await` — обе версии семантически эквивалентны?
- [ ] Ошибки обрабатываются: `try/catch` в async-функциях, `.catch()` в Promise-цепочках?
- [ ] Нет `async` функций без `await` внутри (бессмысленный overhead)?
- [ ] Нет `await` в цикле `for...of` там, где лучше использовать `Promise.all` (параллелизм)?

## Параллельные операции

- [ ] `Promise.all` используется когда все промисы должны успешно завершиться?
- [ ] `Promise.allSettled` используется когда нужен результат каждого независимо от успеха?
- [ ] `Promise.race` используется для тайм-аута или "первый выигрывает"?
- [ ] Нет смешения этих методов не по назначению?

- [ ] Реализация в `limited-concurrency.js` действительно не запускает более N промисов одновременно?

## EventEmitter

- [ ] Событие `error` обрабатывается — нет необработанного `error` эмита, который крашит процесс?
- [ ] Подписчик корректно отписывается через `off()` или `removeListener()`?

- [ ] Используется `emitter.once()` там, где событие должно сработать один раз?

## Streams

- [ ] `streams-demo.js` читает файл через `fs.createReadStream`, а не `fs.readFileSync`?
- [ ] Pipe настроен корректно: обработан `error` на обоих потоках?

## Качество кода

- [ ] Нет `.then()` после `await` на том же промисе (антипаттерн)?
