# Review: 01 HTTP REST CRUD

Контрольные вопросы, по которым я буду оценивать твой код.

---

## HTTP и маршрутизация

- [ ] Все 5 маршрутов реализованы: `GET /tasks`, `GET /tasks/:id`, `POST /tasks`, `PUT /tasks/:id`, `DELETE /tasks/:id`?
- [ ] Неизвестный метод на известном маршруте возвращает `405 Method Not Allowed` (не `404`)?
- [ ] Запрос к несуществующему пути возвращает `404`, а не падает с unhandled exception?
- [ ] Метод и путь парсятся корректно — нет ошибок при лишнем `/` в конце URL?

## Коды ответов

- [ ] `POST /tasks` возвращает `201 Created` (не `200`)?
- [ ] `DELETE /tasks/:id` возвращает `204 No Content` (тело отсутствует)?
- [ ] `GET /tasks/:id` на несуществующий id возвращает `404`?
- [ ] `PUT /tasks/:id` на несуществующий id возвращает `404` (не создаёт новый ресурс)?
- [ ] Валидационные ошибки возвращают `400` (не `500`)?

## Заголовки

- [ ] `Content-Type: application/json` выставляется во всех ответах с телом?
- [ ] `Location: /tasks/:id` присутствует в ответе на `POST /tasks`?
- [ ] Нет заголовков с чувствительными данными (например, путей файловой системы в сообщениях об ошибке)?

## Формат данных и валидация

- [ ] Все ошибки возвращаются в едином формате `{ "error": "CODE", "message": "..." }`?
- [ ] Поле `title` проверяется на наличие (пустая строка тоже отклоняется)?
- [ ] Поле `title` проверяется на максимальную длину 200 символов?
- [ ] Лишние поля в теле POST/PUT не вызывают ошибок (и не сохраняются)?
- [ ] Невалидный JSON в теле возвращает `400`, а не `500`?
- [ ] Возвращаемые объекты tasks имеют стабильную структуру: `{ id, title, ... }`?

## Чтение тела запроса

- [ ] Тело читается через накопление chunks (`req.on("data")` + `req.on("end")`), не блокируя поток?
- [ ] Обработан случай пустого тела при `POST/PUT`?
- [ ] Обработана ошибка `JSON.parse` (try/catch)?

## Качество кода

- [ ] Нет дублирования кода для отправки ответа и ошибки — выделены хелперы `send()` / `sendError()`?
- [ ] `nextId` инкрементируется корректно — нет повтора id после удаления?
- [ ] Нет `console.log` с отладочным мусором в финальной версии?
- [ ] Сервер стартует на порту из `process.env.PORT || 8080` (не захардкожен)?

## Документация и тесты

- [ ] Есть файл `requests.http` или `postman_collection.json` со всеми сценариями?
- [ ] Покрыты сценарии: успех, 404, пустое тело, слишком длинный title, неверный метод?
- [ ] Заполнен `notes.md` с наблюдениями по `curl -v`?

## Статический контент

- [ ] `express.static` подключён через `path.join(__dirname, "public")` — нет хардкода абсолютного пути?
- [ ] `express.static` зарегистрирован **до** маршрутов API (иначе запрос на `/` может не дойти до статики)?
- [ ] `GET /` отдаёт `index.html` с `Content-Type: text/html`, а не JSON?
- [ ] `GET /tasks` продолжает работать как API (статика не перехватывает API-маршруты)?
- [ ] В ответе на запрос статического файла присутствует заголовок `ETag`?
- [ ] В ответе на повторный запрос (без изменения файла) возвращается `304 Not Modified`?
- [ ] При включённом `maxAge` в ответе есть `Cache-Control: max-age=N`?
- [ ] Опция `dotfiles: "ignore"` (дефолт) не позволяет получить `.env` через `GET /.env`?
- [ ] `public/app.js` не содержит захардкоженных секретов или ключей (файл доступен всем)?
