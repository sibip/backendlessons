# Review: 09 Testing

Контрольные вопросы, по которым я буду оценивать тесты.

---

## Структура и организация

- [ ] Тесты разделены на `unit/` и `integration/` (или `__tests__/unit/` и `__tests__/integration/`)?
- [ ] Имена тест-файлов соответствуют тестируемым модулям: `taskService.test.js` для `taskService.js`?
- [ ] `describe` блоки организуют тесты по функции/методу?
- [ ] Названия `it()`/`test()` описывают поведение (`"returns 404 when task not found"`), а не реализацию?

## Unit-тесты

- [ ] Тестируется только публичный интерфейс: входные данные → выходные данные или ошибка?
- [ ] Зависимости (репозиторий, внешние сервисы) замоканы через `jest.mock` или ручной мок?
- [ ] Мок не дублирует реализацию дословно — только контракт (входы → выходы)?
- [ ] Нет реальных HTTP-запросов, соединений с БД или файловой системы в unit-тестах?
- [ ] Тестируются ветки кода: и успешный путь, и путь с ошибкой?

## Интеграционные тесты

- [ ] Тесты используют Supertest (или аналог) — не ручные `http.request`?
- [ ] Тестовая БД отдельная от dev-базы: разный `DATABASE_URL` или отдельный docker-контейнер?
- [ ] База очищается перед каждым тестом или тест-сьютом — нет зависимости от порядка запуска?
- [ ] Тест создаёт все необходимые данные сам (нет зависимости от наличия данных из seed)?

## Покрытие негативных кейсов

- [ ] Есть тест на `404` — запрос к несуществующему ресурсу?
- [ ] Есть тест на `400` — невалидное тело запроса или отсутствующее обязательное поле?
- [ ] Есть тест на `401` — запрос без токена к защищённому endpoint?
- [ ] Есть тест на `409` — дублирование уникального ресурса (если применимо)?
- [ ] Есть тест, когда БД недоступна или возвращает ошибку (мок репозитория бросает исключение)?

## Моки и изоляция

- [ ] `jest.clearAllMocks()` или `jest.resetAllMocks()` вызывается в `beforeEach`/`afterEach`?
- [ ] Нет глобальных переменных, которые один тест изменяет для другого?
- [ ] Нет `setTimeout`, реального `Date.now()` в тестах без управления временем (`jest.useFakeTimers`)?

## Coverage

- [ ] `npm test -- --coverage` запускается без ошибок?
- [ ] Покрытие строк (`Lines`) для сервисного слоя ≥ 80%?
- [ ] Непокрытые ветки задокументированы в `notes.md` с объяснением, почему они не тестируются?
- [ ] Нет тестов, написанных только ради coverage без проверки реального поведения (`expect(true).toBe(true)`)?

## Качество тестов

- [ ] Каждый тест проверяет ровно одну вещь (нет многоцелевых тестов в 50+ строк)?
- [ ] Нет `try/catch` внутри тестов без `fail()` или `expect.assertions(N)` — ошибка не будет молча проглочена?
- [ ] Тесты детерминированы: при запуске 10 раз подряд результат всегда один и тот же?
