# Review: 06 Cache and Redis

Контрольные вопросы, по которым я буду оценивать реализацию кэширования.

---

## Подключение и конфигурация

- [ ] Хост и порт Redis берутся из переменных окружения, не захардкожены?
- [ ] Ошибка подключения к Redis обрабатывается — приложение не падает, а деградирует (запросы идут в БД)?
- [ ] Соединение с Redis переиспользуется (один клиент на всё приложение), а не создаётся на каждый запрос?

## Cache-aside паттерн

- [ ] Порядок операций верный: сначала проверить кэш → если miss → запросить из БД → сохранить в кэш → вернуть?
- [ ] При cache hit данные возвращаются из Redis без обращения к БД (это проверено в логах или тестах)?
- [ ] Кэшируются сериализованные данные (строка через `JSON.stringify`/`JSON.parse`), не объекты напрямую?

## TTL и инвалидация

- [ ] Для всех записей установлен TTL (`EX` / `EXPIRE`) — нет кэша без срока жизни?
- [ ] TTL выбран осознанно и объяснён в комментарии (почему именно N секунд)?
- [ ] При изменении данных (PUT/DELETE) кэш инвалидируется явно (`DEL` нужного ключа)?
- [ ] Нет ситуации stale data: изменение через один endpoint не оставляет устаревший кэш для другого?

## Ключи

- [ ] Ключи Redis имеют понятный и предсказуемый формат: `resource:id` или `resource:list`?
- [ ] Нет коллизий ключей между разными сущностями (не просто числа `"1"`, `"2"`)?
- [ ] Ключи не содержат пользовательских данных без санитизации (нет инъекции через имя ключа)?

## Rate limiter

- [ ] Rate limiter использует `INCR` + `EXPIRE` или `Sliding Window` логику?
- [ ] При превышении лимита возвращается `429 Too Many Requests` (не `403` или `500`)?
- [ ] Заголовок `Retry-After` или `X-RateLimit-*` присутствует в ответе?
- [ ] Лимит задан через переменную окружения, не захардкожен?

## Pub/Sub

- [ ] Publisher и Subscriber используют отдельные подключения к Redis (требование протокола)?
- [ ] Обработан случай, когда подписчик не запущен — publisher не падает?
- [ ] Сообщение содержит полезную нагрузку (`payload`), а не только факт события?

## Измерения

- [ ] Зафиксировано время ответа до и после кэширования (хотя бы в `notes.md`)?
- [ ] Разница в latency наглядна: cache hit значительно быстрее, чем запрос к БД?
