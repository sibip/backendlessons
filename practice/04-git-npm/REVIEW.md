# Review: 04 Git и командная работа

Контрольные вопросы, по которым я буду оценивать историю коммитов и настройки.

---

## История коммитов

- [ ] Все коммиты следуют Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`, `test:` и т.д.?
- [ ] Нет коммитов с сообщениями `wip`, `fix`, `update`, `changes`, `asdf`?
- [ ] Каждый коммит атомарен — одна логическая единица изменений, не "всё сразу"?
- [ ] Тема коммита не превышает 72 символов?
- [ ] После squash rebase история выглядит чистой — нет промежуточных "wip"-коммитов в `main`?

## Ветки и слияние

- [ ] Feature-ветка создана от актуального `main` (не от старого коммита)?
- [ ] PR/merge request имеет описание: что сделано, зачем, как протестировано?
- [ ] После слияния feature-ветка удалена локально и удалённо?
- [ ] Merge-конфликт разрешён корректно: нет маркеров `<<<<<<`, `=======`, `>>>>>>` в коде?
- [ ] После разрешения конфликта результирующий код логически правильный (не просто "взял одну сторону")?

## Git bisect

- [ ] Задокументирован сценарий использования `git bisect`: начальный плохой коммит, хороший коммит, итоговый сломанный?
- [ ] Объяснено, почему bisect эффективнее ручного перебора (O(log n) vs O(n))?

## npm и package.json

- [ ] `package.json` содержит секцию `engines` с указанием версии Node.js?
- [ ] `devDependencies` корректно отделены от `dependencies` (тесты, линтеры — в dev)?
- [ ] Нет `peerDependencies` без явного объяснения зачем они нужны?
- [ ] Секция `scripts` содержит хотя бы: `start`, `dev`, `test`?
- [ ] `package-lock.json` закоммичен (не в `.gitignore`)?

## .nvmrc и .npmrc

- [ ] `.nvmrc` содержит корректную версию Node.js (например, `20.11.0`)?
- [ ] `.npmrc` не содержит токенов или паролей в открытом виде?
- [ ] Оба файла закоммичены?

## .gitignore

- [ ] `node_modules/` в `.gitignore`?
- [ ] `.env` в `.gitignore`?
- [ ] Нет закоммиченных `*.log` файлов, артефактов сборки, IDE-файлов (`.DS_Store`, `.idea/`)?

## Понимание

- [ ] В `notes.md` или `COMMIT_CONVENTION.md` зафиксирована разница merge vs rebase своими словами?
- [ ] Зафиксировано, как откатить последний коммит без потери изменений (`git reset --soft HEAD~1`)?
