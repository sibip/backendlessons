# Review: 08 Auth and Security

Контрольные вопросы, по которым я буду оценивать реализацию аутентификации и безопасности.

---

## Пароли

- [ ] Пароли хешируются через `bcrypt` или `argon2` — не через `md5`, `sha256` или любой обратимый алгоритм?
- [ ] При регистрации пароль хешируется до записи в БД (не хранится plaintext даже временно)?
- [ ] При логине используется `bcrypt.compare` / `argon2.verify` — нет сравнения строк напрямую?
- [ ] Нет `console.log` с паролем или хешем?
- [ ] Ответ API при неверном логине/пароле одинаковый для обоих случаев: "неверный email" и "неверный пароль" — чтобы не раскрывать, существует ли пользователь?

## JWT

- [ ] `JWT_SECRET` берётся из `process.env`, не захардкожен в коде?
- [ ] Подпись токена использует достаточно сильный алгоритм: `HS256` или `RS256`?
- [ ] Access token имеет короткий срок жизни: `15m` – `1h`?
- [ ] Refresh token хранится в БД (или Redis) и можно его отозвать (`logout` делает его недействительным)?
- [ ] При logout refresh token удаляется/инвалидируется на сервере?

## Хранение JWT на клиенте

- [ ] JWT возвращается через `httpOnly` cookie: `res.cookie("token", jwt, { httpOnly: true, secure: true, sameSite: "lax" })`?
- [ ] Нет явного возврата JWT через тело ответа для хранения в `localStorage` (если цель безопасность)?
- [ ] В `notes.md` зафиксированы плюсы/минусы `httpOnly cookie` vs `localStorage`?

## Авторизация (RBAC)

- [ ] Роль пользователя хранится в БД или в JWT-payload, не в сессии на клиенте?
- [ ] Middleware проверки роли не доверяет роли из тела запроса — только из верифицированного токена?
- [ ] Защищённый endpoint возвращает `401 Unauthorized` при отсутствии токена (не `403`)?
- [ ] Endpoint с недостаточной ролью возвращает `403 Forbidden` (не `401`)?

## Защита от атак

- [ ] SQL-запросы используют параметризацию (`$1`, `$2`) — нет конкатенации пользовательских данных в SQL?
- [ ] Входные данные валидируются по схеме — нет raw `req.body` прямо в запрос к БД?
- [ ] Нет возврата полных стек-трейсов пользователю в production?
- [ ] Установлен хотя бы один security-заголовок: `X-Content-Type-Options`, `X-Frame-Options` или через `helmet`?
- [ ] Для CSRF-защиты: SameSite cookie или CSRF-токен (если приложение поддерживает браузерный frontend)?

## Регистрация и идемпотентность

- [ ] Попытка зарегистрировать пользователя с уже существующим email возвращает `409 Conflict` (не `500`)?
- [ ] Ошибка уникальности от PostgreSQL (`23505`) обрабатывается явно — не пробрасывается как внутренняя ошибка?
