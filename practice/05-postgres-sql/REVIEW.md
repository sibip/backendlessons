# Review: 05 PostgreSQL and SQL

Контрольные вопросы, по которым я буду оценивать схему и SQL-запросы.

---

## Схема и DDL

- [ ] Все четыре таблицы созданы: `users`, `products`, `orders`, `order_items`?
- [ ] Первичные ключи определены (`PRIMARY KEY`)?
- [ ] Внешние ключи определены с `ON DELETE` / `ON UPDATE` стратегией (не просто `REFERENCES`)?
- [ ] Поля с ограниченным набором значений используют `CHECK` или `ENUM`?
- [ ] Обязательные поля помечены `NOT NULL`?
- [ ] Временны́е метки `created_at` / `updated_at` имеют `DEFAULT now()` где нужно?
- [ ] Нет хранения паролей в открытом виде в схеме (`users.password` должно быть хешем)?
- [ ] Денежные суммы хранятся как `NUMERIC(10,2)`, а не `FLOAT` (нет проблем с точностью)?

## Индексы

- [ ] Есть индекс на поле, по которому чаще всего делается WHERE или JOIN (например, `orders.user_id`)?
- [ ] Объяснено, почему тот или иной индекс добавлен (не "добавил на всякий случай")?
- [ ] `EXPLAIN ANALYZE` показывает `Index Scan` или `Index Only Scan` для запроса с индексом?
- [ ] `EXPLAIN ANALYZE` для запроса без индекса показывает `Seq Scan` — и это задокументировано?
- [ ] Нет индексов на каждой колонке подряд (понимание, что избыточные индексы замедляют запись)?

## SQL-запросы

- [ ] Есть запрос с `INNER JOIN` (или `JOIN`): минимум 2 таблицы?
- [ ] Есть запрос с `LEFT JOIN` (сохранение строк без совпадения)?
- [ ] Есть запрос с `GROUP BY` + агрегатная функция (`COUNT`, `SUM`, `AVG`)?
- [ ] Есть запрос с `HAVING` (фильтрация по агрегату, не `WHERE`)?
- [ ] Есть запрос с подзапросом или CTE (`WITH ...`)?
- [ ] Нет `SELECT *` в production-запросах — только нужные колонки?
- [ ] Нет SQL-инъекций: параметры передаются через placeholders (`$1`, `$2`), не конкатенацией строк?

## Миграции

- [ ] `schema.sql` и `seed.sql` разделены?
- [ ] `schema.sql` идемпотентен: использует `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`?
- [ ] Seed-данные реалистичны (не только `test`/`foo`/`bar`)?

## Connection pooling

- [ ] В коде используется `Pool` из `pg`, а не создаётся `new Client()` на каждый запрос?
- [ ] Размер пула задан осознанно (или объяснено, почему использован дефолт)?
- [ ] Соединение освобождается через `client.release()` в блоке `finally`?
- [ ] Ошибки подключения к БД обрабатываются (приложение не крашится без БД)?
