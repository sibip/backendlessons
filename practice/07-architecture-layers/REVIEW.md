# Review: 07 Architecture Layers

Контрольные вопросы, по которым я буду оценивать структуру и разделение обязанностей.

---

## Разделение на слои

- [ ] Код разделён на минимум три слоя: `controller`, `service`, `repository`?
- [ ] Controller не содержит бизнес-логику — только разбор запроса и формирование ответа?
- [ ] Service не знает о `req` / `res` — принимает чистые данные, возвращает чистые данные?
- [ ] Repository не содержит бизнес-логику — только SQL/ORM-запросы?
- [ ] Нет прямых вызовов БД из контроллера или из обработчика маршрута?

## Конфигурация окружений

- [ ] Настройки (`DB_HOST`, `REDIS_URL`, `PORT`, `JWT_SECRET`) читаются через `process.env`?
- [ ] Есть отдельный `config.js` / `config/index.js` который собирает все переменные окружения в одном месте?
- [ ] Приложение падает с понятной ошибкой при старте, если обязательная переменная окружения не задана?
- [ ] Файл `.env.example` закоммичен (шаблон без секретных значений)?
- [ ] Файл `.env` находится в `.gitignore`?

## Dependency Injection

- [ ] Зависимости передаются через конструктор или аргументы функции, а не импортируются напрямую внутри функции?
- [ ] Для тестов можно подменить репозиторий мок-объектом без изменения кода сервиса?
- [ ] Нет глобального состояния, доступного из нескольких слоёв (кроме конфигурации)?

## DTO-валидация

- [ ] Входные данные валидируются до попадания в сервис (на уровне controller или middleware)?
- [ ] Валидация использует `joi` или `zod` — не ручные `if (!req.body.title)` цепочки?
- [ ] Ошибки валидации возвращают `400` с конкретным списком нарушений (не абстрактное "invalid data")?
- [ ] Валидация входа и валидация бизнес-логики разделены (разные типы ошибок)?

## Middleware

- [ ] Middleware логирования регистрирует входящий запрос: метод, URL, статус ответа, время обработки?
- [ ] Middleware аутентификации вынесен отдельно и применяется декларативно (не дублируется в каждом роуте)?
- [ ] Централизованный error handler зарегистрирован последним (`app.use((err, req, res, next) => ...)`)?
- [ ] Error handler не возвращает стек трэйс в production-окружении?
- [ ] Middleware вызывают `next()` или отправляют ответ — нет случаев зависания запроса?

## Качество кода

- [ ] Каждый файл/модуль отвечает за одну вещь (Single Responsibility)?
- [ ] Нет "god-функций" длиной 100+ строк без разбивки?
- [ ] Нет магических строк — константы вынесены или именованы?
- [ ] Структура директорий предсказуема: новый человек понимает, куда добавить новый feature?
